# 地铁每日首程客流 · 差分隐私查询平台

地铁数据分析员向合作研究方提供每日首程客流统计的网页服务。基于 **Flask + SQLite**,
对每次新查询的结果添加 **Laplace(0, 2)** 噪声(安全随机源 `secrets.SystemRandom`),
并按 **每次 0.5、每日总额 2** 的隐私预算计费。查询页只显示加噪结果。

另有独立的**优先调查方向抽选**页(`/priority`):运营人员填写 2～12 个候选进出站走廊,
按客流大小以指数机制抽选 1～3 个优先调查方向,只按优先顺序返回选中的方向
(不显示人数或乘客ID),整次抽选合计 ε=0.5,与人数查询共享每日 2 的预算。

## 快速启动

### Docker Compose(推荐)

```bash
docker compose up --build
```

访问 http://localhost:8000 (人数查询)与 http://localhost:8000/priority (优先方向抽选)。
SQLite 数据库保存在名为 `appdata` 的卷中,容器重启后已发布结果、预算消耗与锁定状态均不丢失。

### 本地运行

```bash
pip install -r requirements.txt
python app.py            # 开发模式, 监听 8000 端口
# 或: gunicorn --bind 0.0.0.0:8000 --workers 2 --threads 8 app:app
```

数据库路径由环境变量 `APP_DB` 指定(默认 `./app.db`, 容器内为 `/data/app.db`)。

## 功能与规则

| 规则 | 实现 |
| --- | --- |
| 按日期上传 CSV(乘客ID, 进站, 出站), 每位乘客仅一行 | `POST /upload`, 乘客ID 重复即拒绝; 支持中/英文表头或无表头 |
| 锁定前可整日替换, 首个成功查询或抽选后拒绝替换 | `day_state.locked`, 替换与锁定检查在同一事务内 |
| 选择进/出站集合查询匹配人数 | `POST /query`, 集合与顺序、重复选择无关(排序去重后规范化) |
| 新查询加 Laplace(0, 2) 噪声, 扣 0.5 预算, 每日总额 2 | 逆变换采样 + `day_state.budget_spent` |
| 相同查询复用原结果, 不再扣费 | `queries` 表主键 `(date, in_key, out_key)`, 命中即返回 |
| 并发不超支、相同查询只生成一份结果 | `BEGIN IMMEDIATE` 写事务串行化 + 事务内复查 + 主键约束 |
| 预算不足不返回新结果 | 事务内检查, 不足即回滚并返回 403 |
| 扣费/保存结果/锁定源数据同生共死 | 三者在**同一 SQLite 事务**中提交或回滚 |
| 响应丢失、重启后重查仍返回原值 | 先提交事务再响应; 结果持久化于 SQLite |

### 优先调查方向抽选

| 规则 | 实现 |
| --- | --- |
| 选日期, 填写 2～12 个候选, 每个候选由非空的进站集合与出站集合组成, 候选间站点可重叠 | `POST /select`; 校验数量与空集合, 单侧站点数/长度设上限 |
| 选择 1～3 个名额且不超过候选数 | `slots` 校验, 超过候选数或范围外返回 400 |
| 只按优先顺序显示选中的候选, 不显示人数或乘客ID | 响应只含 `selected: [{in_stations, out_stations}, ...]`(即优先顺序) |
| 客流较大的候选更有机会入选 | 以候选真实人数为分数、敏感度 1 的指数机制(Gumbel-max) |
| 同一乘客可命中多个候选; 整次抽选对增删一名乘客满足 0.5-DP, 多名额共用这 0.5 | Gumbel top-k:每个名额 ε/名额数,基本组合定理下合计恰为 0.5 |
| 安全随机源 | `secrets.SystemRandom` 生成 Gumbel 噪声 |
| 候选及其站点的顺序、重复选择不改变请求身份 | 站点集合排序去重、候选去重排序后取 SHA-256 作为请求键(名额计入请求) |
| 重查返回原顺序且不再扣费 | `selections` 表主键 `(date, request_key)`, 命中即按存储的下标序列返回 |
| 与原查询共享每日 2 的预算, 每次扣 0.5 并锁定当日源数据 | 同一 `day_state` 行累加, 首次成功发布置 `locked = 1` |
| 缺源或额度不足时拒绝 | 事务内检查 `passengers` 是否存在与剩余预算, 分别返回 409 / 403 |
| 交错时结果/扣费/锁定对应同一份完整源数据 | 均为 `BEGIN IMMEDIATE` 写事务; 上传替换同样在写事务内, 与抽选串行 |
| 失败或重启不留半次发布 | 计分读、结果写入、扣费、锁定在同一事务提交或回滚; 事务内异常先回滚再抛错 |

## API

### `POST /upload`
表单字段: `date`(YYYY-MM-DD), `file`(CSV 文件) 或 `csv`(CSV 文本)。
- `200` `{ok, rows}` 替换成功
- `400` CSV 非法(空字段、乘客ID 重复、列数不足等)
- `409` 当天源数据已被首个查询或抽选锁定

### `POST /query`
JSON: `{"date": "2026-11-01", "in_stations": ["西直门"], "out_stations": ["国贸", "望京"]}`
- `200` `{ok, noisy_count, cached, budget_remaining?}` — 只返回加噪人数
- `403` 当日预算不足, 不返回新结果
- `409` 当天缺少源数据
- 相同日期 + 相同站点集合(任意顺序/重复)返回首次发布的同一数值

### `POST /select` 优先调查方向抽选
JSON:
```json
{
  "date": "2026-11-01",
  "candidates": [
    {"in_stations": ["西直门"], "out_stations": ["国贸", "望京"]},
    {"in_stations": ["国贸", "望京"], "out_stations": ["西直门"]},
    {"in_stations": ["北京南站"], "out_stations": ["王府井"]}
  ],
  "slots": 2
}
```
候选也可写成 `[["西直门"], ["国贸", "望京"]]` 两元数组形式;站点集合可用数组或逗号/顿号分隔的字符串。

- `200` `{ok, selected: [{in_stations, out_stations}, ...], selected_count, slots, cached, budget_remaining?}`
  —— 只返回选中的方向,数组顺序即优先顺序;不含人数、得分或乘客信息
- `400` 候选数量不在 2～12、集合为空、名额非法/超过候选数、候选去重后不足 2 个
- `403` 当日预算不足(已用 2),不返回新结果
- `409` 当天缺少源数据

相同日期 + 相同候选集合与名额(任意顺序/重复)返回首次发布的同一优先顺序,不再扣费;
候选及其站点顺序、重复均不影响请求身份。

### 其他
- `GET /api/stations?date=` 当天出现过的全部站点(供页面多选)
- `GET /api/status?date=` 行数、锁定状态、预算消耗
- `GET /api/queries?date=` 当天已发布的全部加噪结果
- `GET /api/selections?date=` 当天已发布的全部优先抽选结果


覆盖: 上传替换与锁定、规范化复用(乱序/重复)、预算上限(4 次新查询)、

Laplace(0, 2) 噪声分布(均值 0、方差 8);
优先抽选的数量/名额校验、只返回选中方向、乱序与重复候选的请求身份、
优先顺序重查与免费复用、共享预算与跨查询交错、
上传与抽选交错时对应同一份源数据、失败回滚不留半次发布、
多名额合计 ε=0.5、大客流候选入选概率更高、并发唯一发布。
